# Deployment architecture (deployment not performed)

The application is a normal Next.js build. Its pages remain prerendered where possible; `/api/google-connector` is a dynamic Node.js Route Handler and the only server-side application endpoint. `output: "export"`, the separate Vercel `api/` file, the custom static server, and `vercel.json` were removed because a static export cannot run a POST Route Handler. The browser sends each connector request to its current origin. The handler validates and forwards it to the selected Apps Script `/exec` URL. It does not persist keys, plans, Sheet data, or history. Plans, in-progress workouts, and history stay in browser localStorage; the standalone v2 connector URL/key and optional Excel handle stay in browser IndexedDB. Existing v1 per-plan keys remain supported.

Vercel should automatically detect Next.js and the `pnpm-lock.yaml`. `package.json` pins Node.js 24.x and pnpm 10.34.6, a pnpm major that Vercel documents as supported. Use the Hobby plan with the default root directory, build command (`pnpm build`), install command (`pnpm install`), and Next.js output. Do not set an Output Directory override. The current MVP needs **no production secrets or environment variables**; each user's connector URL/key is entered in their own browser. There is no paid storage, database, scheduled job, or persistent server process. Verify the automatically selected pnpm version in the first Vercel build log before relying on the deployment.

`pnpm build` stamps a nonsecret build ID and timestamp into the debug page, runs `next build`, and generates `public/sw.js` from the built static assets. The worker precaches the app shell and common routes, caches normal assets, and falls back to cached pages while offline. It deliberately bypasses `/api/` and Next.js RSC requests. Finishing a workout saves local history first, and failed/offline Google sync stays pending for retry. A new worker waits until the user chooses **Reload**; the button is disabled during an in-progress workout, so the app does not force a mid-session refresh.

The proxy accepts only HTTPS URLs matching `https://script.google.com/macros/s/<deployment-id>/exec`, allows only known operations, limits request and response size, and follows at most one ContentService redirect to `script.googleusercontent.com`. It rejects other targets and does not log request bodies or upstream error text. Standalone v2 receives a validated spreadsheet ID for explicit registration/read/write operations and has a separate write command from legacy v1. Apps Script checks the key, registration list, mapping, and bounded date range before writing. The v2 manifest requests only the Google Sheets read/write scope, which can access all spreadsheets available to the deploying account; the connector's command surface remains narrow.

Private workbooks are local-only regression fixtures. `WORKBOOK_FIXTURE_DIR` can point tests at their directory; they are never read at build or server runtime. `.gitignore` excludes workbook formats, secrets, build output, Playwright results, logs, and `.vercel`. Do not copy personal workbook files into `public/` or Git.

Use the [hosted-production checklist](production-deploy-checklist.md) for disposable-Sheet smoke tests. The public production app is already deployed; changes in this repository require a new deployment after review.
