# Manual phone and source checklist

Use disposable workbook/Sheet copies for any source-write test. Do not test writes against the supplied originals. The physical-phone LAN interaction test has been completed; this checklist remains useful for later retests. For hosted tests, follow [the production checklist](production-deploy-checklist.md).

## Physical-phone LAN retest

1. Put PC and phone on the same private Wi-Fi. In PowerShell, run `pnpm dev:lan`. Open the exact printed `http://<pc-ip>:3000` URL on the phone. If the printed IP is the wrong adapter, set `$env:TREINO_LAN_HOST='<Wi-Fi IPv4>'` and restart. Allow the process through Windows Firewall for **private** networks if prompted.
2. Confirm **Choose your training** appears on a fresh browser, and **Import Excel file** opens Plans. Import a *copy* of either supported workbook, review the summary and expandable notes, and choose **Use this training**. A returning browser should open its saved plan dashboard without reselecting the file.
3. Tap **Start workout**, **Mark complete**, and a load input. Navigate back and forward. Reload the page: completion and load must still be present. Open `/debug/` in a second tab if a tap appears inert; note the URL/origin, last action/error, storage status, and service-worker status.
4. Finish the workout, check the local date, save, and open History. Confirm the new session appears with the load; reload and confirm it persists. Switch plans, ensure History shows that plan's records, then switch back. Milena's imported dates should appear as source history and Workout C should show weekly instruction blocks.
5. LAN HTTP may not permit PWA installation or direct File System Access. It **must** permit ordinary workout taps, local history, and the same-origin connector route. To clear an old installed version in Chrome, open site settings for the LAN origin and clear site data or unregister its worker in DevTools **Application → Service workers**, then reload. Clearing site data also removes local plans/history, so export or use a disposable test browser if that data matters. The app automatically unregisters old production service workers when running in development; an update banner asks for reload when a production version changes.
6. Optional Android Chrome remote debugging: enable Developer options and USB debugging on the phone, connect USB, open `chrome://inspect/#devices` on desktop Chrome, allow the phone's USB prompt, then inspect the phone tab for console errors/network requests. The in-app `/debug/` view works without this setup.
