# Excel adapter decision and write safety

## Current two-workbook import and sync

The first adapter described below remains a strict regression path for the original Jonatha workbook. The current import path reads workbook/package XML into a `SourceSnapshot` (`lib/import/snapshot.ts`), then recognizes a supported workout-template family in `lib/import/template-parser.ts`. It imports only `TREINO` sheets, normalizes a dynamic number of workouts, splits one/two/three exercise groups in source order, maps adjacent load and video columns, and converts instruction-only cardio sections to text blocks. Unsupported layouts and critical ambiguities fail safely. The import review presents warnings and existing date counts before adding or refreshing a plan.

The Milena workbook has A/B/C workout sheets, 20 existing dates (6/6/8), grouped triple rows, challenge content, RIR and calorie metadata, and weekly cardio instructions. `TREINO A!H28` is a date-encoded load with display `7.5`; contextual formatted-value handling imports `7.5` and warns. Shared prescriptions, uncertain grouped loads, and an extra hyperlink are review notes rather than silent guesses. The overview sheet is excluded.

Each imported source stores its own sheet names, sheet IDs where applicable, ordinal cells, valid date slots, and a workout fingerprint. Sync re-reads the source and rejects a changed template, duplicate same-workout/date, or full grid. For `.xlsx`, `lib/sync/xlsx.ts` edits only the chosen pre-existing date cell in its worksheet XML, reopens the result, and checks unrelated OOXML package entries. Tests operate on temporary copies of both original workbooks and verify their hashes remain unchanged. Browser direct writes require a persisted File System Access handle, current write permission, a final unchanged-file check, and readback; they are never automatic during workout completion. A concurrent external edit during the final browser write window cannot be made atomic. Safe-copy download remains the fallback and does not claim success until the saved copy is reconnected and verified.

The old paragraphs below document the narrower original workbook adapter and its initial 12-slot preservation tests. Their fixed A/B coordinates do **not** apply to the normalized Milena parser or UI.

The runtime workbook adapter is client-side only. The app's structured plan (`data/workouts.ts`), locally saved sessions (`lib/storage.ts`), and Excel mapping (`lib/excel/mapping.ts`) are separate. The UI never reads Excel cell coordinates. The original `TREINO 1 JONATHA.xlsx` is not bundled into the application or placed under `public/`.

## Method

The adapter uses JSZip to open the `.xlsx` OOXML package and `fast-xml-parser` to **read** workbook metadata, styles, shared strings, sheet cells, hyperlinks, and relationships. For a completion date it changes only the XML text of one pre-existing, empty `<c r="E5" .../>` through `<c r="E16" .../>` cell in `TREINO A` or `TREINO B`, adding a numeric Excel date serial inside `<v>`. It does not serialize whole worksheets or use a cell library to rewrite the workbook. The selected cell's style attribute remains in place, and the adapter validates that its number format is `dd/mm`. It rejects the 1904 date system, changed dashboard formulas, missing/changed sheets, exercise markers and videos, unexpected ordinal/RIR grid values, text dates, occupied cells, and slots outside `E5:E16`.

Before returning an updated file, the adapter reopens the ZIP, verifies CRCs, compares all uncompressed package entries other than the intentionally changed worksheet XML byte for byte, revalidates the workbook, and checks the new date. Therefore drawings/images, relationships, hyperlinks, tables, styles, merges, formulas, and the workbook's existing broken conditional-formatting references are retained as-is. ZIP container metadata and compression may differ, but package entry content is preserved. Tests on a **disposable copy of the actual source workbook** also reverse the single XML edit and compare the entire target worksheet XML to its original. This establishes preservation for the reviewed workbook version, not every possible future Excel layout.

## Connection modes

The Excel page selects a file through the browser; it never asks for or stores an absolute filesystem path. When a secure browser exposes `showOpenFilePicker`, a writable handle, and permission methods, the user can use **direct file** mode. The app checks permission at each sync click, re-reads and validates the current file, checks for duplicate dates and the next empty slot, confirms the file did not change again before writing, then reopens the saved file and verifies the dates. Permission may expire and reconnection may be needed. Concurrent edits in the narrow interval between the final read and write remain a possible browser-level race; the adapter refuses observed changes and does not silently merge files.

Every browser can use **safe copy** mode: select the `.xlsx`, validate it, transform it in memory, and download a new `-updated.xlsx`. The selected file is not overwritten. The local session stays pending after the download because the browser cannot prove that the user actually saved or replaced the file. Reconnecting the saved copy verifies the dates and can then mark the matching local sessions synced. Both modes use the same transformation and validation.

The completion grid has exactly 12 cells per workout. Full grids, changed layout, or an already present same-workout/date value do not trigger a write. Excel stores dates but no application session IDs, so two sessions of the same type on the same day cannot be uniquely represented; the second requires review. Local history remains authoritative, and a failed Excel operation cannot roll back a completed workout.

## Automated safety gate

`pnpm test:excel` reads the reference workbook and makes a temporary copy under the operating system's temporary directory for every write test. The test checks that its output is inside that directory and that the original source hash is unchanged afterward. It covers compatible/incompatible books, A/B first slots, a gap, occupied and out-of-range cells, full grids, duplicate dates, numeric dates and `dd/mm` styles, package integrity, and the preservation of unrelated package entries. The source file is never a write target in tests. Direct browser writes were not performed against the real workbook during development.

If a future workbook revision fails compatibility or preservation tests, disable direct writing for that revision, retain local-first sessions and safe import, then update the mapping and regression fixture deliberately. Do not extend the completion grid into row 17 or formatted empty rows.
