# Diagnostics

Open **Settings → Diagnostics** on the phone. **Download debug report** creates one JSON file on the device without requiring an account. **Send diagnostics** appears when Google is connected and uploads only after an explicit tap; it returns a short `TL-XXXXXXXX` support ID. **Clear local diagnostic log** empties the device event log without changing workouts or previously sent reports. `/debug` remains available for live status and its **Copy diagnostics** action uses the same safe report provider.

The event recorder uses a separate IndexedDB database (`treino-local-diagnostics-v1`). It records meaningful transitions such as app boot, workout start/completion/cancellation, History deletion, social publish/delete and reaction results, plus sanitized application errors. It never records each timer tick. Retention is the newest 500 events from the past 7 days, capped at 128 KiB; oldest events are removed first. The log survives reloads and PWA updates.

`debugReportVersion: 1` includes build/controller status, route, PWA and network state, storage schema and counts, hashed plan/session/workout identity, same-day matcher reason codes, source sync state, Friends status and outbox counts, a count-only importer summary, and the bounded event log. The latest completed session's source state is distinct from the count of all historical pending sessions. Identifiers are one-way local fingerprints. The report omits raw workout records, notes, exact loads, workbook content, Sheet URLs and IDs, email, Google subject, OAuth tokens, cookies, secrets, database connection strings, and raw request or storage bodies. Error reasons are restricted to known codes. The report generator fetches safe account/friend counts only; fetch failures become status codes, not response bodies.

`loadTrace` adds a bounded, report-only provenance view (at most four plans, eight workouts per plan and 120 logical exercises). Each row has random plan/workout/exercise and lineage pseudonyms, source and load cell indices, grouped-exercise index, template/parser and plan versions, and separate pseudonyms for source, imported plan, active-session snapshot, Last and Today loads. Identical normalized loads receive the same random pseudonym within that report; a fresh mapping is generated for every report. The reverse mapping exists only in memory while building the report and is never stored or logged. Missing-value flags, Today's initial and current origins (`LAST`, `PLAN`, `USER`), historical lookup reason, identity-match result and bounded mapping warning codes explain why a load appeared. A source load is represented by the imported plan's load when source-cell provenance exists; the report cannot independently reread the live Sheet. No exercise names, exact loads, workbook names, notes or URLs enter this trace. Cell row/column indices are included only to diagnose neighboring grouped exercises.

Load events cover workbook parsing, mapping, plan refresh, active-session initialization, Last resolution, manual Today changes and mapping ambiguity. They contain event type, time and allowlisted reason codes, never a load value. The server independently validates every trace field and pseudonym format before storing it. The 128 KiB upload cap, explicit Send diagnostics action, private server storage and 14-day retention are unchanged. A trace can reveal a shifted assignment when, for example, exercise 1's Last pseudonym equals exercise 2's plan pseudonym, without revealing either weight. It does not repair historical records; refresh the plan and use the current plan load for Today when an old session snapshot is uncertain.

The upload route requires the existing Google session and same-origin request. It rejects bodies above 128 KiB and independently rebuilds a report from an allowlist of safe fields; browser JSON is never stored directly. Migration `004_support_diagnostics.sql` creates a server-only `treino_support.diagnostic_reports` table. Each report expires after 14 days, expired rows are removed on the next upload, and only the newest 20 reports per user are retained. There is no public report-fetch endpoint. With server-side `DATABASE_URL`, use `pnpm diagnostics:get TL-XXXXXXXX` for an exact, unexpired report lookup. The code is a lookup handle, not authorization. Do not paste `DATABASE_URL` into the command or a bug report.

For phone debugging: download or explicitly send the report soon after reproducing an issue, then share only the short ID if sent. Do not clear app/site data just to capture a report. If a shared History record was deleted while offline, reconnect with the same Google account; Settings also offers **Retry pending Friends deletions**.
