# Friends and reactions V1

Treino Local still stores plans, complete workout history, loads, exercise notes, session notes, videos, timers and source metadata on the device. The server stores only verified social identity, friendships, an opt-in workout summary and one emoji reaction per friend per activity. Home requests only the latest shared workout for each friend and a short list of reactions received on the owner's workouts. There is no cloud workout-history backup or live feed.

The existing verified, allowlisted Google OAuth session supplies the server-side `sub` and email. Social requests never trust a browser-supplied user ID, email or Google sub. They use the same encrypted, HTTP-only session cookie as Sheets. Mutating routes require the configured same origin. Database access uses server-only Postgres.js with `max: 1`, `prepare: false` and required TLS for the Supabase transaction pooler. `DATABASE_URL` is never sent to the browser. Missing database configuration or downtime returns a safe social error without blocking local workouts.

`db/migrations/001_social_v1.sql` creates the private `treino_social` schema, version table, users, friendships, activities and reactions with foreign keys, uniqueness, input checks and modest indexes. Migration 002 adds an additive `manual_shared` flag with a false default; existing activity IDs and reactions remain intact. Keep `treino_social` **out of Supabase's Exposed schemas**. Only the Next.js server uses the connection. Apply pending migrations with `pnpm db:migrate`, then verify with `pnpm db:check`. Never paste a connection string into logs or documents. `pnpm db:smoke` creates uniquely marked temporary rows, reads them and deletes only those rows. `pnpm db:integration` starts a local production server with isolated test identities, exercises actual social APIs, then deletes its own database rows; port 3000 must be free.

Cloud activity fields are: opaque local session ID, workout name, completion timestamp, local date, optional duration, optional completed and total exercise counts. Only those fields are read from the completed local session into the outbox/API payload. No loads, exercise list, notes, YouTube or Sheet URLs, spreadsheet IDs, Excel filenames, OAuth tokens, sync receipts or full History are uploaded. Display name and email are stored on the social user; friend management shows email to the two parties, while Home activity/reaction payloads use display names and never expose emails.

Automatic sharing defaults off in Settings → Friends. After a final local session is saved, an ON account queues its safe summary. An OFF or unknown cached setting creates a durable eligibility check instead; the server setting resolves it when the same account is verified. An item created without any account identity remains available for explicit confirmation after a reload rather than being sent to a possibly different user. A successful local save is never rolled back by social failure. The outbox retries on reconnect, foreground, and Home load. The completion screen and full History session detail show the result and offer **Share with friends** for one session, including a missed historical workout. This is separate from **Share workout**, which opens the native phone share sheet. A manual share remains visible when automatic sharing is OFF; older automatic activities remain hidden. Same-day Add keeps a new session ID. Replace keeps the selected prior ID, so its upsert updates the activity and preserves reactions. Publishing does not require an accepted friend, but only accepted friends can read or react to a visible activity.

Friend requests require both people to open Treino Local with Google once. The recipient accepts or declines in Settings → Friends. Removing a friendship immediately prevents further activity visibility and reactions. A friend can select one of 💪 🔥 👏 😂 ❤️, change it or tap it again to remove it. The owner sees a short received-reaction line on Home after refresh. There are no comments, photos, follower lists, push notifications or real-time subscriptions.
