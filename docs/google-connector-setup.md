# Connect a Google Sheet

Set this up on a **copy** of a supported training Sheet first. No Google Cloud project, OAuth consent screen, Picker, API key, or service account is needed. The connector runs as a small Apps Script attached to that Sheet. It reads only `TREINO` tabs and can write only the next available date in `E5:E16` of the named workout tab. It never accepts a cell address from the app.

1. Open the Google Sheet copy, then choose **Extensions → Apps Script**. Remove the starter code and paste the complete contents of [`WorkoutConnector.gs`](../google-apps-script/WorkoutConnector.gs). Save the project.
2. In the Apps Script editor, choose the `initializeConnector` function and click **Run**. Approve Google's authorization prompt for *your own* bound script. This creates a long random key in **Project Settings → Script Properties** as `WORKOUT_CONNECTOR_KEY`. Copy its value privately. Do not put it in the Sheet, source code, a URL, or a screenshot.
3. Choose **Deploy → New deployment → Web app**. Set **Execute as: Me** and **Who has access: Anyone**. Deploy and copy the URL ending in `/exec`. This public endpoint is protected by the connection key, so keep the key private. If your Google account restricts that deployment access, this connection method cannot run from the app; use Excel import instead.
4. In the app's **Training plans** page, paste the `/exec` URL and key, then choose **Test connection** and **Import training**. Review the workout summary and choose **Use this training**. The key is kept in this browser's IndexedDB, separate from the local plan record. It is sent to the same-origin proxy only for connector requests, never placed in a URL.
5. To write completion dates, open **Source**, choose **Validate source**, then **Enable sync**. Finishing a workout saves it locally first. When online, the app attempts the narrow date write; **Sync pending workouts** retries unresolved entries. A duplicate, full grid, changed source, invalid key, or network failure leaves the local workout in History.

To revoke a key, run `rotateConnectorKey` in the Apps Script editor and reconnect devices using the new value. To stop access entirely, remove the Apps Script web app deployment. The `/exec` URL alone does not grant access. Each browser/device stores its own local training history; the Sheet records dates, not the full app session.

This is a bearer-key design, not per-user Google OAuth. The Web App executes with **your** Google permissions even when a caller has no Google account. Anyone who obtains both the deployment URL and key could read the `TREINO` tabs and register dates within the bounded completion grids until you rotate the key or disable the deployment. Keep both private, use a Sheet copy for the first live test, and do not use this connector for a Sheet containing sensitive information in those workout tabs. The proxy validates the target URL and command shape; it does not replace the script's own key and write checks.

The app uses a same-origin `/api/google-connector` Next.js Route Handler. Local development (`pnpm dev` or `pnpm dev:lan`), local production (`pnpm build` then `pnpm start`), and Vercel all use this same server route. No server secret is configured. Use HTTPS for deployed use; the local phone dev server uses private Wi-Fi HTTP for testing.

A completely independent new Sheet needs its own bound script setup and `/exec` deployment. If you make a copy of a Sheet that already has a bound script, the script **code** is copied with it, but treat the copy as a new connection: open the copy's Apps Script project, run `rotateConnectorKey` there to ensure a fresh key, deploy a **new** Web App from that project, and use the copy's new `/exec` URL and key in the app. Do not reuse the original Sheet's URL or key.

Automated tests mock Apps Script and the proxy. They do not call or write a real Google Sheet. Verify a live connector only with a disposable Sheet copy and inspect the target `E5:E16` cell afterward.
