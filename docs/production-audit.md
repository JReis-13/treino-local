# Production stabilization audit — 2026-10-02

The public deployment at `https://treino-local.vercel.app` was checked **read-only** before this change was deployed. Its home, plans, history, source, workout, finish, debug, manifest, service worker, and setup page returned HTTP 200. An invalid connector target returned HTTP 400. Three Chrome mobile viewport smoke runs navigated the public site without client exceptions. Its service worker identified build `d7e80b8b-20261002T125902`; these checks describe the **currently deployed older build**, not the new v2 code in this commit. No canonical Sheet or workbook was modified.

| Finding | Severity | Root cause | Fix and regression evidence |
| --- | --- | --- | --- |
| Every new Google Sheet needed another bound script | Product blocker | v1 used `getActiveSpreadsheet()` | Added standalone v2 with `openById`, explicit registration, one device-level connector, normal Sheet URL import, and a distinct v2 write command. Legacy v1 remains. Apps Script VM and mobile E2E tests cover both. |
| Local history lacked a backup path | High | Browser storage was the only copy | Settings now exports a validated JSON backup without connector URL/key. Import validates before showing a summary, saves a local safety snapshot, and requires confirmation. Unit tests cover round-trip, malformed/oversized/unsafe input. |
| Installed PWA could activate a new worker while a workout was open | Medium | Worker called `skipWaiting()` during install | New worker waits; app offers Reload after installation, and disables it during an in-progress workout. Production mobile tests cover offline recovery and the update prompt. |
| Source-provided exercise link could be rendered as a raw `href` | Medium | Spreadsheet hyperlinks were not checked at render time | Only HTTPS YouTube watch/short/embed and `youtu.be` links now render. Tests reject script URLs and lookalike hosts. React renders spreadsheet text as text; no raw HTML path was found. |
| Network exception text could reach proxy error response | Medium | Fetch errors reused their message | Proxy now masks network/read exceptions, including private URL or key text. Regression test checks the response. |
| A finish page open across midnight could show yesterday's date | Medium | Date was set only when the page mounted | Automatic local date refreshes while the page is open; an explicit user correction remains authoritative. |
| IndexedDB key write could report success before transaction commit | Low | Promise resolved on request success | Writes now resolve on transaction completion. |
| Small phone layout lacked automated coverage | Low | Only Pixel and iPhone-sized projects existed | Added a 320px touch project to the production E2E suite. |

The connector proxy still permits only exact HTTPS Apps Script `/exec` targets, bounded request/response sizes, one approved Google ContentService redirect, and explicit commands. V2 registration accepts only a validated Sheet ID and stores an allowlist in Apps Script properties. The script accepts no arbitrary range or cell command; completion rechecks mapping, named tab, date slots, duplicates, occupancy, and readback. The v2 manifest declares exactly `https://www.googleapis.com/auth/spreadsheets`. That scope can access every Sheet available to the deploying account, even though connector commands are narrow. An attacker with the deployment URL and master key can register another accessible ID, so the allowlist is **not** a defense against key theft. Rotation and deployment removal are the revocation paths. No per-Sheet token was added because the master key would still authorize registration and token issuance.

The current local data format remains schema v2. Stored records are parsed and validated before use; invalid data blocks writes. Session progress and completion are saved to localStorage before optional remote sync. Offline Google writes remain pending and retryable. Completion mapping drift is blocked by the Apps Script recheck, leaving local history intact. Multi-tab concurrent editing and browser quota/eviction remain localStorage limitations; users should export backups regularly. A physical OS-level PWA install/reopen, real standalone Apps Script authorization, and a date write to a disposable Google Sheet still require manual hosted checks after deployment. No automated test touched a canonical Sheet.

Final local verification: lint and TypeScript passed; 42 unit/parser/Excel/connector tests passed; 30 production-mode mobile/browser E2E cases passed across Pixel, iPhone-sized, and 320px touch viewports. The optimized Next.js build passed with the connector route dynamic and other pages static. The production static asset directory was about 0.94 MiB across 24 files, so no broad parser-bundle optimization was justified in this pass.
