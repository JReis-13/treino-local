# Mobile bug bash and UI audit

Reviewed at 320 × 640, Pixel 7, iPhone 13, and a 430 × 932 Android-like viewport. The browser captures cover the eight core surfaces in `e2e/mobile-visual-audit.spec.ts`, with pending/completed/skipped Focus states, long names, no-load exercises, notes, video, and rest in `e2e/focus-queue.spec.ts`. Physical Android/PWA sharing still requires the short smoke test in `production-deploy-checklist.md`.

| Screen | Bug or clutter found | Change made | Intentional remaining complexity |
| --- | --- | --- | --- |
| Workout List | A sticky Finish bar covered the first load field at 320px; Video, Details, and More competed on every card. | Finish now follows the list. Video remains in Details; cards show completion, load, Details, and More. | Plan and last-used loads remain visible because they guide today's entry. |
| Focus | A middle-exercise completion jumped to the first pending exercise; the sticky Complete button obscured load and details. Later phone use found the pending checkmark misleading and the header too tall. | Advance to the next pending queue member. Use a compact active-workout header, inline equipment/load/rest/video/note context, and distinct Mark complete, Completed/Undo, and Skipped/Undo skip states. Do later and Skip remain under More actions. | Previous/Next can review completed or skipped members without changing the saved queue. Deeper History and note editing remain in Details. |
| Exercise Detail | No state leak found in video/notes checks. | Video remains lazy and closes with the sheet; Focus can open it directly and open the Notes tab from its note preview. | Overview, History, and Notes tabs keep deeper exercise information accessible. |
| Active timer | Timer bar could compete with a sticky Finish bar; no timer-state fault reproduced. | Finish is no longer sticky. Timer retains a compact one-line bar; pause, extension, and resume remain in its sheet. | Timer intentionally persists while navigating during an active session. |
| Share | A rejected image share made a second `navigator.share` call after transient activation was consumed; physical WhatsApp use still did not receive the selected photo. | The later phone correction removes selected photos and generated card export. Native sharing sends only the editable workout text on the original tap. | History sharing, editable text, native recipient choice, and cancel remain. |
| History | Sync metadata repeated on each row; missing duration displayed as “— min”. | Removed sync label from the row and omit unavailable duration; details retain sync information. | One-line note preview remains useful context. |
| Statistics | No calculation defect found in the regression suite; three top metrics and filters were already clear. | Kept the existing summary and charts. | Load trend, duration, and mix remain below the three metrics. |
| Plans | Google connection status occupied a row even for a local active plan. | Removed the redundant status row; connection remains in Settings and the Add training flow. | Active-plan management and switching remain visible. |

State findings: saved data validation accepted repeated logical block IDs, so an ID-based update could mark two exercise states at once. A duplicate queue also made previously saved data fail to load on reopen. The storage read now repairs duplicate IDs deterministically in plans and session snapshots/progress/queues, preserving each existing completion and load value. New sessions reject unresolved duplicate IDs. A regression test failed on the old code and passes with the repair. Imported Jonatha and Milena fixtures already have unique block IDs; the repair covers older or restored data where that invariant was broken. A separate browser test verifies one grouped member stays pending through Focus, List, reload, and Undo.

Share findings: the earlier card File was prepared before the button click, but image sharing remained unreliable in the user's WhatsApp flow. The current phone correction removes user-photo intake and all card export code. The share button makes one native text-share call during the tap, with edited text and no recipient selection inside the app. Cancellation remains distinct from failure. Phone-browser tests inspect the payload, active user gesture, History sharing, and absence of photo/file/download controls.

The added matrix covers ungrouped, pair, and triple completion, Undo, queue/skip combinations, reload, History/Statistics/share counts, duplicate stored IDs, and next-item Focus navigation. Existing suites cover loads, notes, video, timer, Add/Replace, backup/restore, Google/Excel source adapters, OAuth/allowlist, and offline behavior. The occasional OAuth tamper-test failure came from changing the final Base64URL character, which can leave decoded bytes unchanged; the test now alters an authenticated byte deterministically. No canonical spreadsheet or production browser data was changed by automated tests.
