## PWA update lifecycle

A new deployment generates a new `/sw.js` and versioned `treino-<build>` cache. The worker installs its shell, then waits while an older worker controls an open tab or PWA window. The app offers **Update now** only when `registration.waiting` actually exists. A genuine in-progress session under an existing plan defers that action; finishing or cancelling and saving locally makes it available immediately. A selected plan, old Focus position, completed session, or orphaned draft does not defer updates. Tapping **Update now** sends `SKIP_WAITING`, waits for `controllerchange`, and reloads once. An update activated from another window is also offered as an explicit reload; it does not interrupt a workout. No plan, history, local settings, social outbox, or IndexedDB data is cleared.

On `/debug`, compare **Build**, **Controller build ID**, **SW waiting**, **Update UI state**, **Active workout detected**, and **Last update result**. `SW waiting: none` with `Update UI state: idle` means there is no pending update, even if an older banner was seen before reload. If **Retry** appears, reconnect and try it; a waiting worker may also activate from the precached shell while offline. Do not clear site data to recover an update. `/sw.js` is served with no-store headers, and foreground/online events check for a new worker. Development mode alone unregisters old local workers and deletes only `treino-` caches.

`e2e/pwa-transition.spec.ts` runs against an isolated local HTTP server with two distinct real service-worker scripts. It verifies waiting, explicit activation, exactly one reload, the new controller build ID, preserved browser storage, cache replacement, and activation of an already-waiting update while offline on Pixel, iPhone, and 320px emulations. It does not stand in for the separate deployed Vercel smoke test or a real phone. The unit suite covers first install, stale waiting state, retry, multiple-window activation, and cancellation/completion release. The deployed suite tests the current live build and cannot manufacture a second deployment.

The current real-world workbook fixtures are `tests/fixtures/private/TREINO 1 JONATHA.xlsx` and `tests/fixtures/private/TREINO 4 MILENA.xlsx`. The folder is explicitly ignored by Git. Treat originals as read-only and private. Any test that writes workbook data first copies it to a temporary directory, inspects only that copy, removes it, and verifies the original SHA-256 afterward. The old legacy adapter tests use a separately reviewed blank-date Jonatha workbook (`WORKBOOK_REVIEWED_FIXTURE` or the original Downloads file); its fixed hash and empty completion grid differ from the current canonical fixture. Do not commit either workbook or test output. Deployed browser contexts are isolated and never touch phone storage.

Live Google write testing requires an authenticated, explicitly disposable Sheet. The automated Google tests use mocks and readback simulation; they do not write to the canonical Sheet or prove live Google synchronization. Social publishing is a distinct outbox and does not affect source-sync status.

## Source-sync state machine

Before this pass, a completed session persisted three potentially conflicting fields: aggregate `syncStatus`, `completionSyncStatus`, and `loadSyncStatus`. The aggregate sometimes stayed `pending` after a receipt existed or after no load write was required. A bulk error path changed only the aggregate, and Excel safe-copy reconnection depended on a transient message string. Google date retries could see a prior successful write as a duplicate after interruption.

Now the display derives from the persisted completion receipt/operation and the required load operation. A receipt proves completion was synced; unchanged loads require no source write. `pending` means an actual source operation or confirmation remains, `syncing` means work is in flight, `synced` means every required source operation was verified, and `partial` means one operation succeeded while another needs attention. `failed`, `conflict`, `authRequired`, and `sourceUnavailable` identify actionable failures. The aggregate is recomputed on load and on every source-operation update. Excel safe-copy download remains pending until the saved output is reconnected and the prepared slot/load values are verified. Google load writes are idempotent and read back; before a date write, Treino Local persists the intended empty slot, then a retry checks that exact slot on the refreshed Sheet. Foreground/online events retry pending Google operations. Same-day Add remains a separate session; Replace retains an existing completion receipt and only resyncs required loads.

History detail and Home use the same derived source status. A local completion remains saved when source sync fails. Reopen Source and retry after reconnecting; the source operation should move out of pending once readback verifies it. A social publish failure cannot turn source status pending.
